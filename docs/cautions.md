# Cautions

## 설치와 이전 데이터

- 0.6.0부터 앱 이름과 앱 ID가 바뀌어(Keyhub → Tessera, `com.shyunku.tessera`) 설치 프로그램이 Keyhub 0.5.x를 덮어쓰지 않는다. 가져오기가 끝난 것을 확인한 뒤 Windows 설정에서 Keyhub를 직접 제거한다.
- 첫 실행 때 `%APPDATA%\Keyhub\datafiles\v1`의 `shyunku` 계정만 가져온다. `nanoRIPE`는 가져오지 않는다.
- v1 원본 파일은 수정하지 않는다. 가져오기가 끝나도 남아 있으며, 이 파일에는 폴더·항목·키 이름이 평문으로 들어 있다. 새 데이터를 확인하고 백업을 만든 뒤에는 `%APPDATA%\Keyhub` 폴더를 지우는 편이 안전하다.
- 한 번 가져오거나 새로 시작한 뒤에는 `data\legacy-handled` 파일이 생겨 초기화 후에도 이전 데이터 가져오기를 다시 띄우지 않는다. 다시 가져와야 하면 데이터를 초기화하고 이 파일을 지운다.

## 비밀번호와 데이터

- 마스터 비밀번호는 복구할 수 없다. 잊어버리면 데이터와 그 비밀번호로 만든 백업을 열 수 없다.
- 잠금 해제 화면에 "데이터 파일이 손상되었거나 알 수 없는 형식"이 뜨면 비밀번호 문제가 아니다. 초기화하지 말고 `%APPDATA%\Tessera\data`를 복사해 둔 뒤 원인을 확인한다.
- 비밀번호를 바꾸면 데이터 키도 바뀐다. 이미 만든 백업 파일과 예전 데이터 파일 사본은 여전히 예전 비밀번호로 열리므로 필요 없으면 지운다.
- '모든 데이터 교체' 가져오기를 하면 직전 데이터가 `data\backups\tessera-before-replace-<시각>.db`로 남는다(그때의 마스터 비밀번호로 암호화된 상태). 되돌리려면 앱을 끄고 이 파일을 `data\tessera.db`로 복사한다.
- 데이터 초기화는 파일을 삭제할 뿐 디스크에서 완전히 지우지는 못한다(SSD 특성). 다만 파일 내용은 암호화되어 있다.

## 클립보드

- 복사한 값은 설정한 시간(기본 30초)이 지나거나 잠글 때 지운다. 그 사이 다른 내용을 복사했으면 건드리지 않는다.
- 앱이 강제로 종료되면 클립보드를 지우지 못한다.
- Windows 클립보드 기록(Win+V)이나 클라우드 클립보드를 켜 두었다면 복사한 값이 그쪽에 남을 수 있다. 쓰지 않는다면 끄는 것을 권한다.

## 개발

- 이 개발 환경에는 `ELECTRON_RUN_AS_NODE=1`이 설정되어 있다. `npm run dev`/`npm start`는 이를 지우고 실행하지만, Electron을 직접 실행할 때는 주의한다.
- VS Code를 연 상태로 프로젝트 안에 패키징하면 `.asar` 파일이 잠겨 실패한다. `npm run pack:win`은 임시 폴더에서 빌드한다.
- dev 모드 데이터는 `.devdata/`, 이전 데이터 테스트는 `TESSERA_LEGACY_DIR`로 경로를 바꿔 쓴다.
